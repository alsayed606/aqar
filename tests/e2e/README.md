# اختبارات E2E

```bash
npm run build && npm run test:e2e
```

**تحتاج بناءً موجوداً** — تُشغّل `next start` على المنفذ `3123`، فتُخاطب المنتج عبر HTTP كما يُخاطبه Moyasar وVercel Cron.

## لماذا وُجدت

**أربع مراجعات كود متتالية انتهت إلى الجملة نفسها:** الإصلاح في `server action` أو مسار HTTP، **ولا وسيلة في المشروع لاختبار أيٍّ منهما**. السلاسل إمّا SQL على Postgres مُضمَّن، أو دوالّ خالصة `.mts` — **فكل إصلاحٍ في طبقة التطبيق شُحن بلا تحقّق**.

## ما تغطّيه اليوم

**بوّابات المسارات التي تحرس المال:**

| مهمّتا cron | ترفضان بلا ترويسة · بترويسة خاطئة · **وبالسرّ الصحيح بلا `Bearer`** |
|---|---|
| **ويبهوك الدفع** | يرفض حمولةً ليست JSON · بلا سرّ · بسرٍّ خاطئ · **ويقبل السرّ الصحيح ثم يرفض حمولةً بلا `payment_intent`** |
| **`/api/version`** | شكل الجواب، **وأنه لا يُخزَّن مؤقتاً أبداً** |

**والسرّان يُمرَّران في بيئة العملية الابنة** — وNext يُقدّمها على `.env.local`، فالخادم المُختبَر يفرض **سرّ الاختبار** مهما كان على جهاز المطوّر.

## ⛔ وأين تقف عمداً

**كل ما سبق رفضٌ يقع قبل أيّ نداء لـSupabase.** وهذا ليس قصوراً في الطموح، **بل النطاق الأمين الوحيد ما لم يوجد مشروع Supabase للاختبار**:

> `next start` يقرأ `.env.local`، **فطلبٌ يبلغ القاعدة يبلغ القاعدة الحقيقية** — وسلسلة اختبارات تمسّ بيانات الإنتاج **أسوأ من غياب السلاسل**.

**والمسارات الموجبة تنتظر مشروع اختبارٍ مستقلّ — وذلك قرار المالك.**

## ما يستحقّ أن يُضاف حين يوجد ذلك المشروع

- **الويبهوك يردّ 500 حين يفشل التطبيق** — العيب الذي وجدته المراجعة، ولا شيء يمنع عودته.
- **التجديد يعدّ `stranded`** ولا يعدّه `charged`.
- **دورة الدعوة كاملة** — إرسال، ورفضٌ من بريد آخر، وقبول.
- **رفع صورة صيانة** وربطها، ورفض استبدالها.
