# ADR-0003 — بوابة دفع الاشتراك (Payment Gateway)

- **الحالة:** مُعتمد ومُنفَّذ (Accepted) — Sprint G (هجرة `0039`).
- **النوع:** قرار معماري/تقني (قرار تنفيذي: البوابة = Moyasar).
- **التاريخ:** ٢٥ يوليو ٢٠٢٦.
- **المبادئ الحاكمة:** م-١١ (ندمج لا نبني)، هـ-١٩ (لا أسرار في المستودع)، هـ-٢٢ (أمان)، النموذج المالي (هللات صحيحة).
- **يرتبط بـ:** نموذج الاشتراك (هجرة `0036`, Sprint D)، `org_subscription`.

## السياق
`org_subscription` (Sprint D) يحكم الوصول لكنّ تفعيله/تجديده كان **يدوياً عبر SQL**. المطلوب: يترقّي المكتب ويدفع **آلياً** فتُحدَّث حالته فوراً.

## القرار
- **البوابة: Moyasar** (سعودية؛ mada / Apple Pay / بطاقات؛ SAR بالهللات).
- **نموذج الدفع: دفعة لكل فترة** (تفعيل/تجديد فوري) — لا اشتراك متكرّر آلي (مؤجَّل).
- **حدود PCI:** **Moyasar Invoices API** → صفحة دفع **مستضافة**؛ **بيانات البطاقة لا تمسّ خوادمنا إطلاقاً**. المصادقة Basic بالمفتاح السرّي (server-only).
- **التفعيل عبر webhook** `/api/payments/webhook`:
  - يتحقّق من `secret_token` (سرّ مُشترَك)، ويستخدم **service_role حصراً**.
  - **idempotent:** `apply_subscription_payment` يتجاهل النيّة المدفوعة مسبقاً (البوابة تُعيد الإرسال)؛ و`gateway_payment_id` فريد.
  - عند `paid` → يُفعّل `org_subscription` (`status='active'`, `plan_code`, `current_period_end = max(now, current_period_end) + شهر`).
- **المطابقة:** `metadata.payment_intent` (uuid النيّة) يربط دفعة Moyasar بصفّ `subscription_payment`.
- **طبقة واحدة** `lib/payments/moyasar.ts` تعزل البوابة (تبديل Tap/غيرها محصور فيها).

## التبعات
- يتطلّب حساب Moyasar + **المفتاح السرّي** + **سرّ webhook** في env (لا تُلتزَم — هـ-١٩) + ضبط عنوان الـwebhook في لوحة Moyasar.
- **مؤجَّل:** الدفع المتكرّر الآلي (بطاقة محفوظة/تجديد ذاتي/dunning)، proration، الاسترداد الآلي.
- **فاتورة ZATCA لرسوم الاشتراك** من المنصّة للمكتب = **التزام المنصّة الضريبي** (يحتاج CR/VAT للمنصّة) — خارج النطاق، قرار عمل لاحق.

## القرار المطلوب لاحقاً
عند الحاجة للتجديد الآلي: سبرنت «الاشتراك المتكرّر» (توكنة البطاقة + جدولة الخصم + dunning) فوق نفس الجداول.
