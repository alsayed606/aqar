# ADR-0005 — نموذج الصلاحيات (Role → Capability Matrix)

- **الحالة:** مُعتمد ومُنفَّذ (Accepted) — Sprint I (هجرة `0041`).
- **النوع:** قرار معماري/أمني.
- **التاريخ:** ٢٥ يوليو ٢٠٢٦.
- **المبادئ الحاكمة:** هـ-١٦ (فرض الأدوار)، هـ-٦ (العزل)، هـ-٨ (RLS مصدر الحقيقة للصلاحيات).
- **يحلّ محلّ:** قاعدة «المطّلع فقط» في `0033` (كان كل من ليس `viewer` يكتب بلا تمييز).

## السياق
`0033` جعل `viewer` للقراءة فقط، لكن `manager`/`accountant`/`staff` كانوا جميعاً «كُتّاباً» بلا تمييز. المطلوب أدوار واضحة (مدير/محاسب/مدخل بيانات) مفروضة فعلياً.

## القرار
- **٥ قدرات:** `view` · `manage_data` · `manage_finance` · `manage_team` · `manage_billing`.
- **جدول `role_capability`** (مبذور بالهجرة، للقراءة فقط) يربط كل دور بقدراته. المصفوفة:

| الدور | view | data | finance | team | billing |
|---|:--:|:--:|:--:|:--:|:--:|
| owner | ✓ | ✓ | ✓ | ✓ | ✓ |
| admin | ✓ | ✓ | ✓ | ✓ | ✓ |
| manager | ✓ | ✓ | ✓ | ✗ | ✗ |
| accountant | ✓ | ✗ | ✓ | ✗ | ✗ |
| staff | ✓ | ✓ | ✗ | ✗ | ✗ |
| viewer | ✓ | ✗ | ✗ | ✗ | ✗ |

- **`has_capability(org, cap)`** DEFINER (عضوية نشطة + الدور يملك القدرة) هو **بوّابة الكتابة**.
- **RLS:** سياسات تقييدية لكل قدرة تحلّ محلّ سياسات `is_org_writer` في `0033` — جداول البيانات تتطلّب `manage_data` (بما فيها `charge` — تُولَّد بدورة العقد)؛ الجداول المالية (`payment`/`payment_allocation`/`invoice`/`invoice_line`/`owner_remittance`) تتطلّب `manage_finance`.
- **الفريق/الفوترة** تبقى محصورة في owner/admin (`is_org_admin` = `manage_team`/`manage_billing`).
- **الواجهة:** `current_capabilities(org)` تُخفي/تعطّل الأزرار التي لا يملكها الدور — لكن **RLS هو الحاكم**، لا الواجهة.

## البدائل المرفوضة
- قدرات لكل عضو (خارج الدور) — أُجّلت (تعقيد بلا حاجة حالية).
- تعديل المصفوفة من الواجهة — أُجّل (سطح أمني حسّاس؛ تبقى مبذورة بالهجرة).

## التبعات
- إضافة قدرة/تعديل خلية = هجرة جديدة (بيانات `role_capability`).
- لا سطح كتابة على `role_capability` عبر الواجهة (لا يُعدَّل إلا بالهجرة).

## مؤجَّل
صلاحيات على مستوى الحقل · تفويض مؤقّت · سجل تدقيق موسّع للصلاحيات.
